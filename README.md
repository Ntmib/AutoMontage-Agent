# AutoMontage-Agent 🎬

Движок автомонтажа видео для ИИ-агента (Claude Code / Codex). Скидываешь сырое видео говорящей головы – получаешь готовый ролик: субтитры, анимированные плашки, счётчики, картинки под смысл, полноэкранные врезки, музыка, перекадрирование в вертикаль. Всё локально, стиль настраивается.

Не нужно уметь монтировать и не нужен терминал, всё делает агент по твоему запросу.

📐 <b>Шаблоны и стили</b>: каталог со скринами в [docs/TEMPLATES.md](docs/TEMPLATES.md).
Флагман: <b>lesson-presentation</b> (урок/эфир, 9:16 или 16:9). Свой фирменный стиль подключается
внешней темой (`THEMES_EXT`) и в открытый репозиторий не попадает.

---

## Что умеет

- **Субтитры-караоке** – распознаёт речь, ставит субтитры, подсвечивает текущее слово.
- **Плашки и счётчики** – красивые карточки в твоём стиле: текст печатается, цифры бегут, прогресс-бары заполняются.
- **Фото и видео по смыслу** – вставляет подготовленный b-roll на весь экран, при необходимости
  со звуком клипа.
- **Скриншот кадра** – на фразе «сделай скриншот» вставляет твой же кадр в окно редактора.
- **Врезки** – человек пропадает, на весь экран идёт картинка/графика, звук продолжается.
- **Режет паузы и слова-паразиты** – речь звучит плотно и по делу.
- **Музыка** – подкладывает фоновую музыку и приглушает её под голос.
- **Горизонт → вертикаль** – сам перекадрирует и следит за лицом (для Reels/Shorts).
- **Чистит звук и картинку** – громкость под соцсети, iPhone-видео не серое.
- **Зум-ритм** – по запросу меняет крупность плана каждые несколько секунд (динамика).
- **Стиль – параметр** – крафт по умолчанию, можно неон или свой (меняется одним словом).

## Установка – просто скажи Claude

Тебе НЕ нужен терминал. Открой Claude Code (или Codex) в пустой папке и вставь этот запрос:

> Установи движок автомонтажа из репозитория AutoMontage-Agent. Склонируй его, поставь зависимости (Node-пакеты через npm, Python-пакет faster-whisper). Проверь окружение командой `node scripts/doctor.js` и скажи, чего не хватает. Когда всё зелёное, напиши, что можно присылать видео.

Агент всё сделает сам: скачает, поставит, проверит. Шрифты качать НЕ нужно, они уже встроены в репозиторий (рендер работает из коробки).

Проверка окружения одной командой (скажет, чего не хватает):

```bash
automontage doctor      # или: node scripts/doctor.js
```

Что должно быть на компьютере заранее (`doctor` проверит и подскажет):
- **Node.js** (20+) и **Python 3** – обычно уже есть или агент поможет поставить;
- **ffmpeg** – бесплатный; полный browser import использует `libwebp`, `libx264`, `libvpx`,
  `libopus` и AAC. В типовых сборках не хватает именно `libwebp`: тогда обычный монтаж и видео
  продолжают работать, а фото — нет. `doctor` заранее покажет точное предупреждение.

### Установка глобальной командой (Windows / macOS / Linux)

Движок кросс-платформенный. После установки появляется команда `automontage`, доступная **из любой папки**.

```bash
git clone https://github.com/Ntmib/AutoMontage-Agent.git
cd AutoMontage-Agent
npm ci                 # точные Node-зависимости из package-lock.json
pip install -r requirements.txt   # Python: faster-whisper, opencv, numpy
npm install -g .       # ставит глобальную команду automontage
```

### Быстрая проверка свежего клона

Этот короткий маршрут не требует API-ключей или Whisper-модели:

```bash
git clone https://github.com/Ntmib/AutoMontage-Agent.git
cd AutoMontage-Agent
npm ci
npm run doctor
npm run demo
```

`doctor` перечислит обязательные и опциональные части окружения, а демо создаст
`out/demo.mp4` по готовому публичному монтажному листу.

Дальше – из ЛЮБОЙ папки:

```bash
automontage моё-видео.mp4            # результат появится в текущей папке
automontage видео.mp4 --tighten --beat --autopos
automontage --help                  # все опции
```

Пере-генерация картинок-плашек (опционально): скрипты `scripts/shot-*.js` рисуют broll/мок-картинки через Playwright. Основной монтаж их НЕ требует (в репозитории уже лежат готовые картинки). Если хочешь пересобрать их сам – один раз выполни `npx playwright install chromium`.

Особенности по ОС:
- **macOS / Linux** – работает сразу. Если `python3` не находится – поставь через
  `brew install python` (Mac). Если Homebrew-ffmpeg не умеет WebP, установи отдельную полную
  сборку без замены системной: `brew install ffmpeg-full`, затем укажи её каталог через
  `AUTOMONTAGE_FFMPEG_DIR="$(brew --prefix ffmpeg-full)/bin"`.
- **Windows** – ставь Node.js и Python с официальных сайтов (при установке Python отметь «Add to PATH»). ffmpeg: `winget install Gyan.FFmpeg`. Команда `automontage` появится автоматически (npm сам делает `.cmd`-обёртку). Временные файлы, пути и запуск – уже адаптированы под Windows.

### 🔑 Ключи для автоматического lesson-ТЗ

Для автоматической расшифровки смысла и подготовки lesson-ТЗ нужен один LLM-провайдер:
`ANTHROPIC_API_KEY` или `OPENAI_API_KEY`. Ключ задаётся только в локальном окружении,
не пишется в код и не попадает в репозиторий.

Основной Dynamic-монтаж и `automontage demo` работают без API-ключей. Встроенной генерации
изображений через OpenAI API в текущей версии нет: используй свои файлы, публичные активы
или изображение, подготовленное внешним инструментом.

## Формат ролика = формат исходника

По умолчанию агент делает монтаж в том же формате, что и присланное видео:
- прислал **горизонтальное** (16:9) → получишь **горизонтальное**;
- прислал **вертикальное** (9:16) → получишь **вертикальное**.

FPS также наследуется без округления: например, исходные `30000/1001` и `24000/1001`
передаются в Remotion как дробные значения.

Перекадрирование (например, из горизонта в вертикаль со слежением за лицом) делается **только по твоему запросу**. В конце агент может спросить, нужна ли версия в другом формате.

## Один ролик = одна папка проекта

Для работы под ключ используй project-режим. Движок создаст локальную папку
`projects/YYYY.MM.DD_latin-slug/` и сложит туда копию исходника, транскрипт, все версии ТЗ,
музыку, превью, рендеры и один канонический финал. Папка `projects/` игнорируется Git.

Пути из `project.json`, кроме `source.originalPath`, не считаются доверенными: движок принимает
только канонические относительные пути внутри workspace и отклоняет любой уже существующий
symlink-компонент, включая dangling link. Slug проекта имеет вид `safe-project-01`; legacy
`--id` допускает только буквы, цифры, `_` и `-`. Финальная копия с `--outdir` независимо
проверяет через `lstat` каждый существующий компонент каталога и финала, отклоняет обычные
и dangling symlink, создаёт отсутствующие каталоги по одному и публикует файл через
непредсказуемый exclusive temp без следования статической ссылке назначения.
`source.originalPath` намеренно хранит абсолютный путь только как provenance исходника, а не как
workspace-путь. Эти проверки рассчитаны на manifest и symlink, существующие в момент проверки;
не давай недоверенным процессам конкурентную запись ни в папку проекта, ни в `--outdir`.

Исходник каждого render получает уникальный временный lease в `public/.automontage/`, поэтому
другой build не может подменить его байты. Но часть промежуточных и legacy-файлов остаётся в
общем `tmp/`, поэтому в одном checkout всё ещё запускай только одну активную сборку. Для
параллельных роликов используй отдельные clone/worktree.

Создать новый lesson-проект с форматом исходника:

```bash
node scripts/build.js video.mp4 --template lesson \
  --project "AI agent lesson" \
  --aspect source \
  --theme lesson-neutral
```

Для lesson `--theme` можно не указывать: встроенная `lesson-neutral` используется по
умолчанию. Dynamic сохраняет прежний default `craft`; приватные темы задаются явно через
`--theme <id>` и `THEMES_EXT`.
Если явный внешний id не найден, `THEMES_EXT` не задан или `theme.json` повреждён,
сборка останавливается до Remotion: незаметной подмены на `craft` нет.

После проверки ТЗ утвердить конкретную ревизию и отрендерить её:

```bash
node scripts/project/approve-brief.js \
  projects/2026.08.05_ai-agent-lesson \
  brief/v01-draft.lesson.json

node scripts/build.js \
  projects/2026.08.05_ai-agent-lesson/input/source.mp4 \
  --template lesson \
  --project-dir projects/2026.08.05_ai-agent-lesson \
  --brief brief/v01-approved.lesson.json \
  --version-label first-render
```

Следующая правка использует тот же `--project-dir`, но новый `--version-label`, например
`new-music` или `ducking`. Старые версии остаются в `renders/`, принятый результат копируется
в `final/<slug>.mp4`. Без `--project` и `--project-dir` старый вывод в `out/` продолжает работать.
Approval сначала атомарно публикует новые Markdown и JSON без замены существующих файлов, а
`project.json` обновляет последним. При ошибке прежний draft остаётся текущим; stale или занятый
другим процессом проект возвращает конфликт вместо перезаписи истории.
Первичный draft создаётся по тому же правилу: номер версии выбирается только внутри project
transaction, поэтому параллельный запуск не может перезаписать уже появившийся JSON/Markdown.

Approved lesson может задать отдельный локальный video для конкретной сцены через
`scene.faceSrc`: либо `assets/...` внутри project, либо web-relative путь из repository
`public/` (также допустим явный префикс `public/`). Перед Remotion файл проверяется как
канонический regular video без symlink, копируется в одноразовый immutable render bundle и
заменяется в props на `.automontage/.../media-N.ext`. Main `audioSrc` всегда остаётся исходным
видео; звук custom face video не добавляется. Absolute paths, URL, traversal и не-video
расширения отклоняются до запуска Remotion.

Top-level `faceSrc`/`audioSrc` не являются источником доверия: lesson builder отдельно передаёт
канонический source alias, и оба поля обязаны ему точно соответствовать. Утверждённые media
копируются в owner-only системный temp, который Remotion получает через `--public-dir`; host path
не попадает в props. Baseline фиксируется до render callback, после него сверка строгая: даже
восстановленный byte-for-byte файл с новым `ctime` закрывает сборку.

### Локальная проверка Review Workbench

Review Workbench необязателен и работает только с уже созданной project-папкой. Обычный запуск
read-only: он показывает видео, waveform, слова, сцены и аудит таймингов, но не вызывает Remotion
и не меняет `project.json`, brief или историю рендеров.

```bash
automontage review --project-dir projects/2026.08.20_demo
automontage review --project-dir projects/2026.08.20_demo --edit
automontage review --project-dir projects/2026.08.20_demo --no-open
```

`--edit` разрешает перенос общей границы соседних сцен и назначение фото или видео в готовую
`broll`-сцену. Свободно менять текст, тип сцены и эффекты здесь нельзя.

#### B-roll через браузер: от файла до готового ролика

Перед началом нужны project-папка с draft и хотя бы одна сцена `broll`. Для фото сначала
запусти `automontage doctor`: строка про WebP должна быть `OK`. На macOS предупреждение
исправляется без удаления обычного ffmpeg:

```bash
brew install ffmpeg-full
export AUTOMONTAGE_FFMPEG_DIR="$(brew --prefix ffmpeg-full)/bin"
automontage doctor
automontage review --project-dir projects/2026.08.20_demo --edit
```

Дальше работа выглядит так:

1. Нажми **«Добавить медиа»** и выбери один файл. Дождись сообщения об успехе. Во время
   обработки запрос может оставаться открытым несколько минут: сервер делает безопасную
   рабочую копию внутри именно той project-папки, которая передана в `--project-dir`.
2. Проверь карточку файла в дорожке «Медиа проекта». Загрузка **не выбирает сцену сама** — это
   защита от случайной подмены. В нужной карточке «Сцена N» отдельно выбери имя файла.
3. Для фото выбери положение. **«Заполнить кадр»** (`cover`) убирает полосы ценой обрезки краёв;
   **«Вписать целиком»** (`contain`) показывает весь кадр и при другом соотношении сторон
   оставляет поля.
4. Для видео сначала прокрути маленький плеер к нужному моменту и нажми
   **«Начать с текущего места»**. Review привяжет старт к ближайшему кадру, сохранит позицию
   маленького плеера после проверки и покажет строку **«Используется: начало–конец»**. Конец
   вычисляется из текущей длительности сцены и обновляется после границы, Undo или Redo. Затем
   выбери положение и звук:
   - **«Без звука»** — слышен исходный голос, звук b-roll выключен;
   - **«Тихо поверх голоса»** — звук b-roll идёт примерно на −18 dB под исходной речью;
   - **«Вместо голоса»** — исходный голос плавно уходит только на время сцены, звук b-roll
     становится основным.
5. Один загруженный ролик можно выбрать в нескольких сценах и задать каждой свой старт,
   кадрирование и звук. Для видео без аудиодорожки доступны только «Без звука».
6. Нажми **«Сохранить»** один раз. Контрольная точка: в project-папке появилась новая пара
   `brief/vNN-draft.lesson.md` + `.json`; старые draft, approved и renders не изменились.
7. Закрой Review, проверь новую ревизию, явно утверди именно её и только затем рендери:

```bash
node scripts/project/approve-brief.js \
  projects/2026.08.20_demo \
  brief/vNN-draft.lesson.json

node scripts/build.js \
  projects/2026.08.20_demo/input/source.mp4 \
  --template lesson \
  --project-dir projects/2026.08.20_demo \
  --brief brief/vNN-approved.lesson.json \
  --version-label broll-video
```

Поддерживаются изображения AVIF/GIF/JPEG/PNG/WebP до 25 MiB, не больше 12 000 пикселей
по стороне и 100 мегапикселей; видео MP4/MOV/M4V/WebM до 1 GiB, 30 минут, 4096 пикселей
по стороне и 8 847 360 пикселей в кадре. Выбранный отрезок обязан помещаться в файл:
`старт + длительность сцены ≤ длительность видеопотока` с покадровым округлением. Для режима
«Вместо голоса» тот же отрезок обязан целиком помещаться и в аудиопоток; `mute` и `mix`
ограничены только видеопотоком. Длинный звук обрезается по видео, короткий не растягивается.
Контейнерная длительность не заменяет длительность видеопотока.

Импорт идёт по одному файлу и может заметно нагрузить CPU: мастер нормализуется, а для видео
отдельно создаётся браузерный WebM-прокси. Начальный допуск требует не меньше
`4 × размер файла + 512 MiB`, затем свободное место заново проверяется перед каждой фазой с
учётом рассчитанных master/proxy/copy budget. Кодировщики и копии имеют жёсткие лимиты:
до 128 MiB для изображения, 2 GiB для video master и 512 MiB для proxy. Превышение лимита
или нехватка места возвращает `507`, удаляет только owned partial files и разрешает повторить
импорт. После autorotate нечётная сторона видео дополняется максимум одним пикселем без crop
или растяжения; фото сохраняет исходную геометрию. Ограничение 120 FPS относится к видео;
неподвижное изображение можно импортировать в проект с более высоким output FPS.
У анимированного GIF/WebP в V1 используется только первый кадр.

Частые ошибки:

- фото падает на обработке — в ffmpeg нет `libwebp`; повтори `automontage doctor` и команду
  с `AUTOMONTAGE_FFMPEG_DIR` выше;
- файл появился, но сцена не изменилась — это ожидаемо, выбери его в самой сцене;
- «Тихо поверх» и «Вместо» недоступны — у видео нет аудиодорожки;
- старт не принимается — до конца ролика не хватает длительности сцены, выбери более ранний
  момент или более длинный файл;
- «Вместо» не принимается при допустимой картинке – аудиопоток короче выбранного отрезка;
- импорт вернул `507` – освободи место или выбери меньший файл и повтори; незавершённый owned
  import будет безопасно убран;
- «Файл добавлен, но экран не обновился» – импорт уже завершён и повторно загружать файл не
  нужно; перезагрузи страницу, чтобы получить свежий список медиа;
- Save заблокирован — дождись окончания импорта/проверки или нажми «Повторить проверку» после
  сообщения о занятом проекте.

Metadata v2 хранит visual `durationSec` и отдельный `audioDurationSec`. Старый image bundle v1
остаётся читаемым, но video bundle v1 нужно переимпортировать: его прежняя длительность могла
быть контейнерным максимумом, поэтому безопасно восстановить аудиограницу без исходного probe
нельзя. Импортированные активы неизменяемы: нет удаления или перезаписи файла тем же id.
Чтобы заменить байты, загрузи новый файл и назначь его сцене. Отдельной нормализации громкости
каждого клипа тоже нет, поэтому слишком громкий или тихий оригинал лучше подготовить заранее.

Перетаскивание границы притягивается к ближайшему слову или кадру; стрелки ←/↓ и →/↑ двигают
строго на один кадр, поэтому не застревают на слове. Home ставит границу на первый допустимый
кадр, End — на последний. Timing audit отдельно помечает frame- и word-подсказки.
Перенос меняет `end` левой и `start` правой сцены; поздние сцены не сдвигаются. Undo/redo живут
только в памяти браузера до явного Save. Save не перезаписывает выбранный draft или approved
brief: он атомарно создаёт новую пару `vNN-draft.lesson.md` + `.json` и одну запись manifest.
Общий project mutation lease не даёт Save, approval и render одновременно менять один manifest;
после аварийного завершения lease умершего локального PID восстанавливается автоматически, а
live/foreign owner не удаляется. Browser import и его startup cleanup используют этот же lease:
второй Review сохраняет активные quarantine/stage bytes, а после hard exit удаляются только
объекты с durable owner record и совпавшим inode. UUID и возраст файла ownership не доказывают.
Cleanup сначала уносит exact target в private tombstone и сохраняет позднюю подмену. При завершении
Review по SIGINT/SIGTERM активный import отменяется, зависший child ограниченно эскалируется до
SIGKILL, а CLI ждёт полного import-finalizer: controller, quarantine и project lease освобождаются
до exit 130/143 и доступны следующему запуску. Это одинаково для прямого Review CLI и публичной
команды `automontage review`, которая пересылает сигнал дочернему серверу и ждёт его cleanup.
При
`409` браузер блокирует timeline, b-roll и Save до безопасной повторной проверки либо загрузки
свежего disk state; устаревшие команды не применяются автоматически. Approved-ревизии остаются
неизменными.

Draft никогда не передаётся в render. В Review нет кнопок approval и render: новую ревизию нужно
отдельно утвердить через `scripts/project/approve-brief.js`, затем собрать существующей командой
с `--brief`, как показано выше.

Сервер слушает только `127.0.0.1` и создаёт случайный session token. Все `/api/*` и `/media/*`
запросы требуют token; POST дополнительно принимает только Origin текущей loopback-сессии.
Ссылка с token даёт доступ к локальному предпросмотру, поэтому её не публикуют. `--no-open` или
ошибка запуска браузера создают exclusive временный URL-файл с правами `0600`; CLI печатает
только его путь. Файл удаляется при закрытии сервера, обычном `SIGINT`/`SIGTERM` или через
10 минут. Локально прочитай URL из этого файла и передай его браузеру, не копируя в чат или
журнал. Если ffmpeg не сумел
построить waveform, Review всё равно открывается с обычной временной шкалой.

Review намеренно не поддерживает свободное редактирование текста, эффекты, keyframes, masks,
глобальный ripple, смену типа сцены, browser export и OpenCut runtime/project format. Такие
возможности требуют отдельного дизайна и не входят в безопасный контур 1.3.0.

## Большие файлы через Telegram (для тех, кто ставит бота)

Если подаёшь видео через своего Telegram-бота, у облачного Bot API лимит – бот принимает/отдаёт максимум 20–50 МБ. Чтобы работать с большими файлами (до 2 ГБ) прямо в чате:

1. Подними локальный Telegram Bot API сервер (`telegram-bot-api`, есть Docker-образ) на своей машине, например на `localhost:8081`.
2. В настройках своего бота укажи `apiRoot` / `baseApiUrl = http://localhost:8081` (опция есть в grammY, telegraf, node-telegram-bot-api и др.).
3. После этого бот сможет принимать и отправлять большие видео без сжатия.

Без этого большие ролики придётся передавать через облако (Google Drive и т.п.) или в сжатом виде.

## Как пользоваться

1. Пришли агенту видео (говорящая голова). Если файл большой – через ссылку на Google Drive.
2. Скажи, что хочешь. Примеры запросов:

> Смонтируй это видео в моём крафт-стиле. Субтитры, плашки на ключевых словах, музыку lo-fi на фон приглушённую.

> Сделай вертикальный Reels из этого горизонтального видео, следи за лицом. Добавь ритмичный зум – новый план каждые 3 секунды.

> На фразе «сделай скриншот» вставь мой кадр. Сгенерируй 2 реалистичные картинки под смысл.

3. Агент соберёт монтаж и пришлёт готовый ролик.

**Авто-адаптация под видео** (по запросу): агент может сам подстроить цвета графики под палитру твоего ролика (сохранив твой бренд-цвет) и расставить плашки по кадру, чтобы не перекрывали лицо и не были шаблонными. Скажи «подстрой под видео» или «сделай не шаблонно».

Не хочешь ничего расписывать – просто напиши «смонтируй», агент сам предложит вариант и покажет.

## Стиль под себя

По умолчанию – «крафт» (тёплый кремовый + терракот). Хочешь другой – скажи агенту: «сделай в неоновом стиле» или «вот мои цвета: …». Новый стиль добавляется одним файлом-темой за пару минут.

## Распознавание речи – модель на выбор

Субтитры делаются локально моделью Whisper. Модель **скачивается один раз** при первом запуске и дальше работает офлайн (не качается на каждое видео).

| Модель | Вес | Точность (рус) | Когда брать |
|---|---|---|---|
| `base` | ~140 МБ | средняя | слабый сервер, черновик |
| `small` | ~460 МБ | хорошая | лёгкий баланс |
| `large-v3-turbo` | ~1.6 ГБ | почти макс | **по умолчанию** (баланс) |
| `large-v3` | ~3 ГБ | максимум | мощный сервер, чистовик |

По умолчанию – `large-v3-turbo`. Скажи агенту «используй small» или «поставь large-v3» – он переключит. Есть и облачный вариант (без скачивания, но платно и нужен интернет): OpenAI Whisper API / Yandex SpeechKit.

### Версии и история изменений

Текущая версия: **v1.3.0**. Источник номера – `version` в `package.json` и корневая запись
в `package-lock.json`; состав релиза описан в [CHANGELOG.md](CHANGELOG.md).

Проект использует SemVer: первая цифра меняется при несовместимых изменениях, вторая – при
новых обратно совместимых возможностях, третья – при исправлениях. Будущая работа сначала
попадает в `[Unreleased]`, а при выпуске переносится в секцию версии с датой. Публичный релиз
помечается Git-тегом `vX.Y.Z`.

Репозиторий публичный, поэтому общая техническая документация хранится в Git, а локальные
дневники разработки, рабочие исходники, рендеры, ключи и приватные темы игнорируются.

### Защита от случайного коммита ключей

На рабочей машине один раз активируй хранимый в проекте pre-commit hook:

```bash
git config core.hooksPath .githooks
```

Перед каждым коммитом hook запускает `gitleaks` по staged-файлам и блокирует коммит при
подозрении на API-ключ, токен или пароль. В GitHub тот же контроль повторяется на каждый
push и pull request с полной историей репозитория. В настройках репозитория дополнительно
включены GitHub Secret Scanning и Push Protection. Не обходи локальную проверку через
`--no-verify`.

`npm audit --audit-level=high` блокирует high/critical advisories. Пять текущих moderate
записей сводятся к одному transitive `file-type` advisory внутри optional `--autotheme`;
точная цепочка, граница входа и дата обязательного пересмотра записаны в
[`SECURITY.md`](SECURITY.md). Это временное исключение, а не заявление об отсутствии риска.
Release-checker принимает его только когда `reviewedAt` совпадает с датой текущего релиза,
не находится в будущем, а ровно пять записей chain совпадают с candidate `package-lock.json`.

### Проверка Git-дерева и кандидата в релиз

Release-checker читает выбранное committed Git-дерево, а не грязную рабочую папку. Поэтому
локальные исходники и незакоммиченные transcript/captions не влияют на результат:

```bash
npm run check:release
npm run check:release -- --tree HEAD --base origin/main
npm run check:release -- --release
```

Первая команда безопасна для shallow CI и проверяет текущее development-дерево; будущие
изменения могут оставаться в `[Unreleased]`. Вторая дополнительно проверяет изменённые
относительно базы публичные файлы. Третья включает строгий режим публикации: `[Unreleased]`
обязан быть пустым. Перед публикацией локально запускай `npm run check:release -- --release`
и `npm run smoke:release`: smoke последовательно собирает короткий approved lesson и Dynamic
project, полностью декодирует оба MP4 и оставляет пути к двум финалам в выводе.

## Демо

Пример готового ролика: [`examples/demo-preview.mp4`](examples/demo-preview.mp4). Это
нейтральное синтетическое видео с титрами, карточками и b-roll, без людей и без музыки.

Собрать демо самому одной командой (без ключей, без скачивания whisper-модели):

```bash
automontage demo      # или: npm run demo
```

Она монтирует лёгкое тест-видео по готовому листу `examples/scenario-demo.json` и кладёт
результат в игнорируемый `out/demo.mp4`. Сгенерированные transcript/captions также живут
в `out/` и не меняют отслеживаемые файлы `src/data/`.
