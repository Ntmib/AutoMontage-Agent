# План внедрения улучшений (из hyperion-reels + OpenMontage)

Источник идей: разбор двух репозиториев (Horosheff/hyperion-reels, calesthio/OpenMontage). Берём только то, что усиливает НАШ узкий конвейер (Remotion + faster-whisper + монтажный лист). Каркасы оркестрации, TTS, видео-нейронки, паблишинг — НЕ берём.

Принцип интеграции: всё встраивается в существующий `scripts/build.js` как опциональные шаги-флаги. Ничего не ломаем — старый путь работает без флагов.

---

## ФАЗА 1 — приоритет 1 (дёшево, большой эффект). Цель: плотный монтаж + чистый звук/картинка.

### 1.1 Порезка пауз + слов-паразитов (tighten) — ✅ ГОТОВО
Источники: hyperion `montage_plan.detect_silence_gaps` / `_filter_silences_for_montage`; hyperion `detect_fillers` (FILLER_RE); OpenMontage `silence_cutter.py`.
Что делаем:
- [ ] Объединить в `scripts/tighten.js` (расширить текущий cut-pauses.js): на вход transcript(words) → строит keep-интервалы.
- [ ] Пауза режется, если gap между словами > `--maxGap` (дефолт 0.6с), НО с guard: (а) не резать паузу в первые `--hookGuard` сек (дефолт 1.5с — защита хука); (б) не опускать итог ниже `--minDur`; (в) оставлять `--pad` 0.1с дыхания.
- [ ] Слова-паразиты: RU-регэксп `^(э+|эм+|ну|типа|короче|значит|как бы|это самое)$` → их интервалы тоже вырезаются (флаг `--fillers`, по умолчанию on).
- [ ] После реза — НЕ перетранскрибировать заново, а ПЕРЕСЧИТАТЬ таймкоды слов (маппинг: каждое оставшееся слово получает новое время = старое минус суммарно вырезанное до него). Быстрее второго whisper и точнее.
- [ ] Выдаёт: tightened.mp4 + пересчитанный transcript.json → дальше обычный build-captions.
Встраивание: в `build.js` флаг `--tighten` между шагами транскрипции и субтитров.
Критерий готовности: на тестовом ролике речь заметно плотнее, субтитры синхронны, хук не обрезан.
Сложность: средняя. Кредиты: 0. Риск: рваная склейка на стыках → смягчить pad + проверить на глаз.

### 1.2 Финиш-проход качества (аудио + картинка) — ✅ ГОТОВО
Источники: hyperion `audio_polish.py` (loudnorm), `quality_presets.finishing_filters` (HDR→SDR, lanczos, unsharp).
Что делаем:
- [ ] `scripts/finish.js` — ffmpeg-проход ПОВЕРХ отрендеренного Remotion mp4:
  - аудио: `loudnorm=I=-14:TP=-1.5:LRA=11` (громкость под соцсети); опц. второй проход `alimiter`, если пики > -1dB.
  - видео (по флагу `--hdrfix`, автодетект smpte2084/arib-std-b67): `zscale=t=linear...,tonemap=hable,zscale=t=bt709...` — iPhone-исходники перестанут быть серыми.
  - резкость (флаг `--sharpen`): `unsharp=5:5:0.8`; при даунскейле — `scale=...:flags=lanczos`.
- [ ] Всё отключаемо флагами; дефолт: loudnorm on, hdrfix авто, sharpen off.
Встраивание: в `build.js` финальный шаг после `remotion render`.
Критерий готовности: громкость ролика ≈ -14 LUFS (проверить `ffmpeg loudnorm print_format`), iPhone-исходник не серый.
Сложность: низкая (готовые фильтры). Кредиты: 0.

## ФАЗА 2 — приоритет 2 (польза, средняя сложность).

### 2.1 JSON-схема монтажного листа + reason + валидатор — ✅ ГОТОВО
Источник: OpenMontage `schemas/artifacts/edit_decisions.schema.json` (образец подхода).
Что делаем:
- [ ] `schema/scenario.schema.json` — JSON-схема нашего листа: source, theme, width/height/fps/durationInFrames, blocks[] с per-type валидацией пропсов, `additionalProperties:false`.
- [ ] Добавить необязательное поле `reason` в каждый блок (самодокументация: зачем этот блок здесь).
- [ ] `scripts/validate.js` (Ajv) — валидирует лист ПЕРЕД рендером; понятная ошибка вместо падения в Remotion на 200-м кадре.
- [ ] (опц.) разделить лист на `scene_plan` (замысел) и `blocks` (реализация) — пока НЕ обязательно, отметить как идею.
Встраивание: `build.js` вызывает validate перед render; отдельная команда `node scripts/validate.js лист.json`.
Критерий готовности: битый лист (неизвестный type / лишнее поле / плохой тайминг) отклоняется с внятным сообщением.
Сложность: низкая-средняя. Кредиты: 0.

### 2.2 Музыка + ducking (сайдчейн под голос) — ✅ ГОТОВО
Источник: OpenMontage `edit_decisions.audio.music.ducking` (модель параметров; реализацию пишем сами на ffmpeg).
Что делаем:
- [ ] Секция в листе: `audio: { music: { file, gain_db, ducking: {threshold_db, reduction_db, attack_ms, release_ms} } }`.
- [ ] `scripts/mix-music.js` — ffmpeg `sidechaincompress` (голос управляет приглушением музыки) + `amix`; применяется в финиш-проходе.
- [ ] Библиотека 2-3 бесплатных крафт-треков в `assets/music/` (royalty-free).
Критерий готовности: под музыкой голос разборчив, музыка приглушается на речи и оживает в паузах.
Сложность: средняя. Кредиты: 0.

### 2.3 Хук-скоринг — ✅ ГОТОВО (базовый)
Источник: hyperion `analyze_hook_quality_2026`.
Что делаем:
- [ ] `scripts/hook-score.js` — RU-адаптация паттернов (pattern_interrupt / curiosity_gap / value_promise / number / urgency), скор первых 3 сек.
- [ ] Пока — вспомогательный: подсказывает агенту, где сильный момент. Полноценно нужен, когда добавим авто-нарезку длинного в шортсы (сейчас нарезки нет).
Критерий готовности: скрипт печатает скор хука и топ-моменты по транскрипту.
Сложность: низкая-средняя. Кредиты: 0. Приоритет внутри фазы: низкий (отложить до авто-нарезки).

## Порядок и оценка
1. Фаза 1 целиком (1.1 → 1.2) — максимум пользы на единицу усилий. Прямой прирост качества ролика.
2. Фаза 2.1 (схема) — страховка от битых листов; 2.2 (музыка) — эмоция.
3. Фаза 3 — по мере надобности (reframe при мультиформате, гейт при потоке роликов, checkpoint при длинных).

Что осталось за скобками (сознательно НЕ внедряем): оркестрация субагентами, TTS, видео-нейронки, Kie API, HyperFrames, backlot, паблишинг на платформы, ink-theater. Обоснование — в разборе (профиль другой / оверинжиниринг / хрупко).

## ФАЗА 4 — адаптивная раскладка (не «шаблон») — идея (feedback Димы 2026-08-01)
Проблема: позиции плашек зашиты в блоках (InfoCard всегда слева-снизу) → монтаж выглядит шаблонным.
- 4.А (просто, ~день): позиция как ПАРАМЕТР блока (`pos: left|right|center` + сторона входа). Агент, который и так смотрит кадры видео, раскладывает плашки осмысленно под композицию каждого ролика (лицо справа → плашка слева и т.п.). Правки: добавить pos во все блоки + в схему; варьировать в монтажном листе.
- 4.Б (средне): авто-анализ кадра (OpenCV — уже стоит): находить свободные зоны (без лица) для плашек + вытягивать доминирующие цвета видео и подгонять акцент темы под палитру ролика.
Рекомендация: начать с 4.А — сразу убирает шаблонность малой кровью.

## Ничего не ломаем
Все улучшения — опциональные флаги/шаги в build.js. Базовый путь «видео → монтажный лист → рендер» работает без них. Внедрять и коммитить по одному, с проверкой на тестовом ролике.
