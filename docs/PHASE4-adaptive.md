# Фаза 4 — Адаптивный движок (уйти от шаблона)

Цель: движок подходит любому пользователю с любым стилем. Плашки раскладываются под композицию КАЖДОГО кадра (не «всегда слева»), а цвета графики подстраиваются под палитру видео (с сохранением бренда). Основано на 2 исследованиях (2026-08-01).

Принцип интеграции (как везде): двухфазно — **Python/Node анализ (offline, раз на видео) → JSON → Remotion читает**. Ничего в базовом пути не ломаем; адаптив включается флагом.

---

## ЧАСТЬ 1. Адаптивная раскладка плашек

### Инструменты (проверено: стоят)
OpenCV 5.0 (`cv2.saliency` — Spectral/FineGrained), mediapipe 1.0 (Face Detection, SelfieSegmentation). rembg НЕ нужен.

### Ключевой вывод индустрии
Проф-редакторы (Opus/Submagic/Captions) НЕ возят субтитры по кадру — держат их в стабильной safe-zone, а различают ролики стилем/подсветкой/emoji/анимацией и **auto-reframe** (двигают КАДР под лицо). Значит:
- **поток субтитров** — оставить в предсказуемой нижней safe-zone (читаемость важнее);
- **адаптив — только для акцентных плашек** (LabelTop / InfoCard / CounterCard / SubtitleCard-событие). Это наша дифференциация.

### 4.1 Позиция как ПАРАМЕТР блока — ✅ ГОТОВО
- [ ] Добавить в блоки проп `pos` (`left|right|center` × `top|bottom`) + сторона входной анимации. Сейчас позиции захардкожены — вынести в пропсы, дефолт сохранить.
- [ ] Добавить `pos` в JSON-схему.
- [ ] Правило-антипод к лицу: mediapipe Face bbox → центр лица; лицо слева → плашка справа, справа → слева, крупно по центру → сверху/снизу. + чередование стороны между соседними плашками (anti-repeat).
- [ ] Агент (я) при монтаже смотрю кадры и проставляю `pos` осмысленно.
Результат: шаблон «всегда слева» исчезает почти без CV. Риск промаха мал (лицо обычно в одной половине).

### 4.2 Анализ кадра → placement.json — ✅ ГОТОВО (analyze-frames.py + --autopos)
Python-препроцесс `scripts/analyze-frames.py`:
- [ ] Сэмпл 1 кадр / 0.3–0.5с (или по сегментам faster-whisper) — не покадрово.
- [ ] mediapipe **Face Detection** → bbox (фолбэк Haar, иначе «центр»).
- [ ] mediapipe **SelfieSegmentation** → маска человека → инверт = маска фона (учитывает плечи/руки, не только лицо).
- [ ] Наложить **safe-zone маску** (запретные зоны, см. ниже).
- [ ] Сетка кандидатов 3×4 по третям; score ячейки:
  `score = 0.4·долях_фона + 0.2·(1−saliency) + 0.15·(1−laplacian_var) − 0.15·близость_к_лицу − 0.1·штраф_повтора_стороны`.
- [ ] Выбрать max; записать позицию + рекомендованный цвет текста (по яркости зоны).
- [ ] Вывод: `placement.json` = `[{start,end,x,y,anchor,side,textColor}]`.

### 4.3 Стабилизация + вариативность (средне)
- [ ] Позиция фиксирована ВНУТРИ сегмента речи; смена только на паузе/границе фразы (у нас есть word-timestamps).
- [ ] EMA/медиана позиции по сегменту (saliency шумит между кадрами — обязательно сглаживать, иначе дёрганье).
- [ ] Правило третей + детерминированный микро-джиттер от индекса (воспроизводимо).

### Safe zones (9:16, консервативно)
Универсальная зона: центральный прямоугольник **~900×1400 в 1080×1920** (отступы: верх ~200, низ ~400, право ~140, лево ~90). Право и низ — почти всегда запретны (кнопки/подписи платформ). Адаптив играет в зоне левый-центр / верх-середина.

## ЧАСТЬ 2. Авто-палитра из видео

### Ядро — material-color-utilities (Google), готовое «тема из картинки»
npm `@material/material-color-utilities` (есть и Python-порт). Полный цикл: пиксели → `QuantizerCelebi` (Wu+k-means в LAB, 10–100мс) → `Score.score` (фильтр по хроме + разнообразию hue, отбрасывает серо-бурый фон) → `themeFromSourceColor(seed)` → роли (primary/surface/on-*) с гарантией контраста через `ContrastCurve`. Единственное открытое решение полного цикла — закрывает извлечение + роли + контраст разом.

### 4.4 Извлечение палитры — ✅ ГОТОВО (palette.js)
- [ ] Сэмпл кадров: `ffmpeg -vf "thumbnail=100,scale=320:-1" -frames:v 20` (thumbnail берёт характерные кадры, не переходные; downscale обязателен). Отбросить кадры с очень низкой яркостью/хромой.
- [ ] Пиксели (≤400k) → `QuantizerCelebi` + `Score` → seed-цвет (или top-N). Альтернатива для MVP: `node-vibrant` → свотч `Vibrant` + готовый `bodyTextColor`.
- ВАЖНО: квантовать в LAB/перцептивном пространстве, НЕ в RGB (иначе «грязь»).

### 4.5 Роли + контраст — ✅ ГОТОВО (WCAG 10:1 проверено)
- [ ] `themeFromSourceColor(seed)` → primary/secondary/surface/on-surface.
- [ ] Вся палитр-математика в **OKLCH** (L = яркость; фиксируем L под контраст, крутим hue/chroma).
- [ ] Контраст **WCAG ≥ 4.5:1** для текст/фон (формула relative luminance + CR). Не хватает → двигать ТОН фона (L), hue не трогать. Авто-выбор чёрный/белый текст. Для субтитров поверх видео — обязательный scrim (полупрозрачная подложка) или тень/обводка.

### 4.6 brandLock — ✅ ГОТОВО (--brandLock 0..1)
Параметр пользователя `brandLock ∈ [0..1]`:
- **1.0** (по умолчанию, «brand-anchor, video-tint»): акцент/CTA = жёстко бренд-цвет (терракот); фон/нейтрали подстраиваются под температуру видео (seed-hue с низкой хромой).
- **0.5**: hue бренда слегка тянется к видео (≤15°) + второй акцент как гармония (аналог/комплемент) от seed.
- **0.0**: почти Material You — всё из видео, бренд лишь один из входов scoring.
Так каждый пользователь держит свой стиль, но графика «сидит» в ролике.

### 4.7 Стабилизация палитры (средне)
- [ ] НЕ пересчитывать тему покадрово (главный риск — фликер). Считать **одну палитру на сцену/ролик**.
- [ ] Детект сцен: `ffmpeg select='gt(scene,0.4)'`; при смене сцены — плавный кросс-фейд токенов.
- [ ] Экспорт в наши дизайн-токены (адаптер MCU→theme): заменить захардкоженные craft-цвета на генерируемые `bg/accent/text/subtitleBg`.

## Порядок внедрения (рекомендация)

1. **4.1** (позиция-параметр + антипод + чередование) — ~день, сразу убивает «шаблон». Самый высокий ROI.
2. **4.4–4.5** (палитра из видео + контраст через MCU) — движок подстраивает цвета под ролик; ядро готовое (MCU), риск читаемости закрываем WCAG+scrim.
3. **4.6** (brandLock) — гибкость под чужой стиль (ключ к «широкому применению»).
4. **4.2–4.3** (полный CV-анализ раскладки) — когда захотим максимум качества раскладки.
5. **4.7** (стабилизация палитры по сценам) — для длинных роликов со сменами планов.

## Риски (честно)
- Static saliency шумит между кадрами → обязательна временная стабилизация (иначе дёрганье плашек).
- Haar-детектор лица ненадёжен на повёрнутой голове → mediapipe основной.
- Палитра покадрово → фликер → одна тема на сцену.
- Нечитаемый текст — главный UX-риск → WCAG 4.5 + scrim/тень обязательны.
- Safe-zone цифры платформ плавают → берём консервативный максимум.

## Что даёт в итоге
Движок перестаёт быть «крафт-шаблоном»: плашки ложатся под композицию каждого видео, цвета подстраиваются под ролик, а пользователь через `brandLock` держит свой фирменный стиль. Готово к широкому применению (каждому — свой вид, а не один шаблон).
