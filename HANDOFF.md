# HANDOFF – полный процесс автомонтажа видео агентом (от А до Я)

Документ-передача. По нему агент/ученик воспроизводит весь пайплайн: из сырого видео говорящей головы → готовый ролик с субтитрами, крафт-плашками, счётчиками, broll-врезками и сгенерированными картинками. Всё локально и бесплатно; OpenAI – только для генерации картинок (опционально).

Репозиторий: `AutoMontage-Agent` (Remotion-проект). Результат этого репо – движок «монтажный лист (JSON) → видео».

---

## 0. Что это делает (результат)

Вход: видео.mp4 (говорящая голова, вертикаль ИЛИ горизонт).
Выход: тот же ролик с наложенной анимированной графикой в едином стиле:
- караоке-субтитры (текущее слово подсвечено);
- плашки-события, инфо-карточки, счётчики с накруткой;
- полноэкранные broll-врезки (человек пропадает → картинка/скрин с зумом);
- сгенерированные картинки под смысл речи.
Стиль – параметр (крафт по умолчанию; неон и любой другой – сменой одного поля).

## 2. Установка с нуля

```bash
# 1. проект
git clone <repo> AutoMontage-Agent && cd AutoMontage-Agent
npm install                       # remotion, react, @remotion/fonts

# 2. транскрипция
pip install faster-whisper

# 3. playwright chromium (если не стоит)
npx playwright install chromium

# 4. шрифты – ОПЦИОНАЛЬНО. Для рендера качать НЕ нужно: ttf уже лежат в public/fonts/
# и инлайнятся в base64 (src/fonts-data.js). Системные шрифты в ~/.fonts нужны ТОЛЬКО
# если пересобираешь картинки-плашки через Playwright (scripts/shot-*.js).
mkdir -p ~/.fonts && cd ~/.fonts
curl -sL "https://github.com/google/fonts/raw/main/ofl/oswald/Oswald%5Bwght%5D.ttf" -o Oswald.ttf
curl -sL "https://github.com/google/fonts/raw/main/ofl/jetbrainsmono/JetBrainsMono%5Bwght%5D.ttf" -o JetBrainsMono.ttf
curl -sL "https://github.com/google/fonts/raw/main/ofl/onest/Onest%5Bwght%5D.ttf" -o Onest.ttf
fc-cache -f ~/.fonts
# те же ttf кладём в проект: public/fonts/ (нужны Remotion) и они инлайнятся в base64

# 5. (опц.) ключ для генерации картинок – через переменную окружения, НЕ в код
export OPENAI_API_KEY=...   # у ученика – свой
```

## 4. Полный пайплайн от А до Я (что происходит с видео)

```
[1] ffprobe          → width, height, fps, duration (аспект наследуется!)
[2] ffmpeg           → извлечь аудио wav 16k mono
[3] faster-whisper   → transcript.json: сегменты + words[{w,s,e}]
[4] build-captions   → captions.js: фразы по 3-4 слова / по паузам
[5] (опц.) cut-pauses→ вырезать паузы > 0.55с, пересобрать видео
[6] монтажный лист   → JSON: какой блок, когда, с каким текстом/картинкой
     ├─ агент читает транскрипт и расставляет плашки по СМЫСЛУ
     ├─ ищет якорные слова (напр. «плашка», «скриншот») по таймкодам
     └─ подбирает broll: локальный HTML или gpt-image-2 под смысл
[7] картинки         → broll: (а) HTML→PNG или (б) gpt-image-2 (quality=high, БЕЗ текста)
[8] Remotion render  → накладывает графику на видео, наследуя аспект
[9] выход .mp4       → отправка как ДОКУМЕНТ (иначе Telegram сплющит вертикаль)
```

Команда-обёртка (шаги 1-8):
```bash
node scripts/build.js <видео> [--theme craft] [--scenario лист.json] [--id имя] [--model base]
```
Без `--scenario` собирается ЧЕРНОВОЙ лист (лейбл + субтитры + эвристический CTA) в `out/<id>.scenario.json` – агент правит его под смысл и перезапускает с `--scenario`.

## 5. Как агент собирает монтажный лист (главный «ум» процесса)

Это не автоматика, а работа агента с транскриптом. Алгоритм:
1. Прочитать transcript.json – понять о чём речь.
2. Найти якорные моменты по словам и их таймкодам (напр. `греп` слов «плашка», «скриншот», «результат», цифры).
3. Расставить блоки СИНХРОННО смыслу:
   - число в речи → `CounterCard` (накрутка);
   - «вот здесь появится плашка» → `SubtitleCard accent` ровно на этих секундах;
   - «покажу картинку/скриншот» → `BrollFullscreen` с нужным изображением;
   - финал-призыв → `CTACard`.
4. Субтитры `CaptionsAuto` – на всю речь (сверху для горизонта, снизу для вертикали, чтобы не конфликтовать с плашками).
5. Проверить рендером несколько кадров (`npx remotion still ... --frame=N`) ДО полного рендера.

Пример боевого листа – `src/scenario-job1.js`.

## 6. Библиотека блоков (что принимает каждый)

| type | назначение | пропсы |
|---|---|---|
| LabelTop | верхний лейбл-бренд | text |
| CaptionsAuto | караоке-субтитры | groups, pos('top'/'bottom'), offset |
| InfoCard | инфо-карточка + прогресс | tag, title, pills[], countPill{value,suffix}, progress |
| CounterCard | крупный счётчик 0→N | label, value, unit |
| SubtitleCard | плашка-реплика/событие | text, accent, sub |

Тайминг у всех: `start` (сек), `end` (сек, опц.). Вид берётся из активной темы.

## 7. Темы (стиль как параметр)

`src/theme/craft.js` – БАЗА:

Новая тема = копия craft.js + свои цвета + регистрация в `theme/index.js` (~10 минут). `cyber.js` – пример (графит + неон, glow:true). Тот же монтажный лист рендерится в любой теме сменой поля `theme`.

## 8. Генерация картинок

Два пути:
- Локальный (0₽): HTML-шаблон (`scripts/broll-*.html`) → Playwright PNG. Так сделаны график «РОСТ Х10» и скриншот-окно (реальный кадр видео в рамке приложения). Текст рисуем нашими шрифтами – кириллица чистая.
- gpt-image-2 (OpenAI, платно): `POST /v1/images/generations`, `model:"gpt-image-2"`, `quality:"high"`, размер под аспект (1536x1024 гориз / 1024x1536 верт). ПРАВИЛО: в промпте задавать крафт-палитру и «NO text, NO letters» – кириллицу модель пишет криво, текст добавляем плашкой поверх. Проверять новейшую модель через `/v1/models`.

## 9. Грабли и решения (критично – сэкономит агенту часы)

1. **Шрифты в Remotion виснут.** `delayRender + FontFace.load()` и даже `@remotion/fonts` подвисают в headless при параллельном рендере (Remotion замораживает таймеры → fallback-таймауты не срабатывают). РЕШЕНИЕ: инлайнить шрифты как base64 `@font-face` прямо в DOM через `<style>` (`fonts-data.js` + `fonts.js` → `<FontStyle/>` в Timeline). Синхронно, без промисов.
2. **Telegram сплющивает вертикаль.** Видео 9:16 через sendVideo показывается ~квадратным (бот не шлёт width/height). РЕШЕНИЕ: отправлять смонтированный ролик как ДОКУМЕНТ (файл), не как видео.
3. **Аспект.** Наследуется автоматически – графика кладётся поверх исходного кадра (overlay/Composition = размер источника). Вертикаль→вертикаль, горизонт→горизонт. Для горизонта субтитры ставить сверху (`pos:'top'`), плашки снизу – не конфликтуют.
4. **Рендер медленный на CPU (~1 fps).** 12с ≈ 2.5 мин, 53с ≈ 20 мин. Длинные ролики – рендерить в фоне (не в основном потоке, иначе оборвётся) или порциями (`--frames=A-B`) со склейкой ffmpeg.
5. **Точность субтитров.** whisper-base быстрый, но ошибается в словах. Для чистовика – модель крупнее (`--model medium/large`) или ручная правка групп в captions.
6. **Двойной фон.** Не запускать `nohup ffmpeg &` внутри фонового вызова – процесс рапортует успех и умирает. Запускать напрямую в фоне.
7. **Рассинхрон звука/видео при нарезке – самая частая причина: `concat`-демуксер (`ffmpeg -f concat -c copy`) в несколько проходов подряд.** Каждая склейка независимо закодированных кусков даёт 10-30мс расхождения видео/аудио на стыке (AAC режет кадрами ~21мс, `-ss/-to` округляет границы) – за несколько проходов набегает секунда и больше, «голос убегает от губ». РЕШЕНИЕ: резать ВСЕ нужные диапазоны ОДНИМ вызовом ffmpeg через `filter_complex trim+concat` (пример – `scripts/tighten.js`), никогда не гонять результат через `concat` повторно.
8. **Тот же баг – внутри `render-chunks.js` (порционный рендер длинных роликов).** Порции (h264, каждая своим независимым вызовом Remotion) склеивались через `concat -c copy` – на 15-20 стыках это теряло кадры (проверено: 5325 кадров на входе → 5301 на выходе, ~1 секунда потеряна), а аудио бралось цельным из исходника и оставалось полной длины → тот же «голос впереди видео». ИСПРАВЛЕНО: склейка порций теперь через `concat`-ФИЛЬТР (покадрово, без потерь) вместо демуксера – см. код. **Проверка после любой нарезки/сборки, всегда:**
   ```bash
   ffprobe -v error -select_streams v:0 -show_entries stream=duration,nb_frames,avg_frame_rate -of default=noprint_wrappers=1 файл.mp4
   ffprobe -v error -select_streams a:0 -show_entries stream=duration -of default=noprint_wrappers=1 файл.mp4
   ```
   `avg_frame_rate` должен быть точным (`25/1`, не дробным вроде `477090000/19165199` – дробное значение = кадры потеряны при склейке). Разница длительностей видео/аудио больше ~20-30мс – сигнал, что дальше по конвейеру будет рассинхрон.
9. **Вырезание слов-паразитов (`tighten.js`) может оставлять «дыры» тишины.** Если резать слово-паразит («вот», «ну», «короче») строго по его границам `[w.s, w.e]`, соседние естественные микропаузы (человек обычно и мнётся перед «вот» – там и так пауза) остаются нетронутыми и складываются в заметную секундную тишину на месте одного короткого слова – обрезка становится «слышна». РЕШЕНИЕ (уже в коде): при вырезании филлера захватывать интервал не по самому слову, а от конца предыдущего слова до начала следующего (с PAD) – так исчезает и слово, и пауза вокруг него разом.

## 10. Как ставить задачу агенту (для учеников)

Режим A (быстрый): прислать видео → «смонтируй». Агент транскрибирует, собирает черновой лист, показывает, рендерит.
Режим B (точный): видео + короткое ТЗ:
```
• Стиль: крафт (или свой) – дефолт крафт
• Выделить цифры/факты: «...»
• Broll (картинка на весь экран) и где: 0:08 – что показать
• Ключевые слова под подсветку
• Финал (CTA): «...»
• Настроение: спокойное / энергичное
```
